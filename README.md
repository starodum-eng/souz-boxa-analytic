# Союз-Бокса · Сквозная аналитика

Дашборд сквозной аналитики для клуба единоборств. Собирает данные из
рекламных кабинетов и CRM, сводит их в единую воронку
**реклама → визиты → лиды → продажи** и считает CPL, CAC, ROMI.

## Стек

- **Next.js (App Router, TypeScript)** — фронт + серверные API-роуты. Хостинг: **Vercel**.
- **Neon (Postgres) + Drizzle ORM** — БД-витрина.
- **Vercel Cron** — синхронизация данных по расписанию (раз в сутки, 06:00 UTC / 09:00 МСК).
  На плане Hobby cron допускается не чаще раза в день; для дневных метрик этого достаточно.

## Источники данных

| Источник | Что берём | Модуль |
|----------|-----------|--------|
| Яндекс.Директ | расход, показы, клики по кампаниям | `src/integrations/yandex-direct.ts` |
| Яндекс.Метрика | визиты, пользователи, достижения целей по UTM | `src/integrations/yandex-metrika.ts` |
| VK Реклама | расход, показы, клики | `src/integrations/vk-ads.ts` |
| Яндекс.Бизнес | показы/действия карточки | `src/integrations/yandex-business.ts` |
| Fitbase | клиенты, продажи абонементов (выручка) | `src/integrations/fitbase.ts` |

Связующий ключ между источниками — **UTM-метки**. Чтобы сквозная атрибуция
работала, во всех рекламных кампаниях UTM должны быть единообразными и
пробрасываться в Fitbase при создании клиента.

## Архитектура данных

```
Внешние API ──(Vercel Cron, раз в 3 ч)──▶ ETL (src/lib/etl.ts) ──▶ Neon
   сырьё:  ad_spend / web_sessions / clients / sales
                                          │
                          пересчёт витрины daily_metrics
                                          │
                    Дашборд (/api/metrics) читает из витрины
```

- Сырые таблицы хранят данные «как есть» (+ поле `raw` с исходным ответом).
- `daily_metrics` — агрегат по `дню × источнику` с производными метриками.
- `sync_log` — журнал синхронизаций (виден на дашборде).

## Запуск локально

```bash
pnpm install
cp .env.example .env         # заполнить токены и DATABASE_URL
pnpm db:push                 # создать таблицы в Neon
pnpm dev                     # http://localhost:3000
```

Ручной запуск синхронизации (локально, если задан CRON_SECRET — передать заголовок):

```bash
curl http://localhost:3000/api/cron/sync
```

## Деплой на Vercel

1. Импортировать репозиторий в Vercel.
2. Подключить Neon через маркетплейс Vercel (переменная `DATABASE_URL` подставится сама)
   или задать `DATABASE_URL` вручную.
3. Прописать остальные переменные окружения из `.env.example`
   (токены источников, `CRON_SECRET`).
4. `vercel.json` уже содержит расписание cron — Vercel подхватит его автоматически.

## Что доработать перед боем

- **Токены/эндпоинты источников.** Пути и авторизация в интеграциях помечены
  комментариями; часть (VK Реклама, Fitbase, Яндекс.Бизнес) нужно сверить с
  актуальной документацией под ваши доступы.
- **UTM-маппинг** кампаний Директа/VK → канал в `recomputeDailyMetrics()`
  (сейчас атрибуция по `utm_source` через LIKE — упрощённая, last-click).
- **Аутентификация дашборда** (сейчас страница открыта). Для одного клуба
  достаточно Vercel Password Protection или простого middleware.
